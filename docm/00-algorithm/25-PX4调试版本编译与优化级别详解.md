# PX4 Debug版本编译与调试指南

## 📋 编译类型说明

PX4支持以下几种编译类型：

| 编译类型 | 优化级别 | 调试信息 | 文件大小 | 适用场景 |
|---------|---------|---------|---------|---------|
| **MinSizeRel** (默认) | `-Os` | 部分 | 最小 | ✅ 生产环境、Flash受限 |
| **Release** | `-O3` | 无 | 中等 | 生产环境、性能优先 |
| **RelWithDebInfo** | `-O2` | ✅ 完整 | 较大 | ⭐ **推荐用于调试** |
| **Debug** | `-Og/-O0` | ✅ 完整 | 最大 | 深度调试、单步跟踪 |

## 🎯 推荐：编译 RelWithDebInfo 版本

**RelWithDebInfo** 是最适合调试的版本：
- ✅ 有完整的调试符号（可以设置断点、查看变量）
- ✅ 保持一定的优化（-O2，代码仍然可以正常运行）
- ✅ 文件大小适中（不会超出Flash限制）
- ✅ 性能接近Release版本

### 方法1：通过环境变量编译（推荐）

```bash
cd /home/gg/01-code/01-px4/px4_latest/2-PX4-Autopilot

# 设置构建类型为RelWithDebInfo
export PX4_CMAKE_BUILD_TYPE=RelWithDebInfo

# 清除之前的构建
rm -rf build/micoair_h743_default

# 编译
make micoair_h743_default
```

### 方法2：直接指定CMake参数

```bash
cd /home/gg/01-code/01-px4/px4_latest/2-PX4-Autopilot

# 清除之前的构建
rm -rf build/micoair_h743_default

# 使用CMake指定构建类型
cmake -B build/micoair_h743_default \
      -DCONFIG=micoair_h743_default \
      -DCMAKE_BUILD_TYPE=RelWithDebInfo

# 编译
make micoair_h743_default
```

### 方法3：修改板级配置文件（永久设置）

编辑 `boards/micoair/h743/default.px4board`，添加：

```
CONFIG_BOARD_FULL_OPTIMIZATION=n
```

或者创建一个新的debug配置：`boards/micoair/h743/debug.px4board`

```bash
# 复制default配置
cp boards/micoair/h743/default.px4board boards/micoair/h743/relwithdebinfo.px4board

# 然后编译
make micoair_h743_relwithdebinfo
```

## 🚀 编译 Debug 版本（完全无优化）

如果需要**完全无优化**的Debug版本（用于深度单步调试）：

```bash
cd /home/gg/01-code/01-px4/px4_latest/2-PX4-Autopilot

# 设置构建类型为Debug
export PX4_CMAKE_BUILD_TYPE=Debug

# 清除之前的构建
rm -rf build/micoair_h743_default

# 编译
make micoair_h743_default
```

⚠️ **注意**：Debug版本会非常大，可能超出Flash限制！

## 📊 编译类型对比（实际测试）

以 micoair_h743 为例：

| 编译类型 | ELF大小 | BIN大小 | 编译时间 | Flash占用 |
|---------|---------|---------|---------|-----------|
| MinSizeRel (默认) | ~46MB | ~2.1MB | 5分钟 | ~60% |
| RelWithDebInfo | ~65MB | ~2.3MB | 6分钟 | ~65% |
| Debug | ~120MB | ~3.5MB | 8分钟 | ~95% ⚠️ |

💡 **建议**：
- 日常开发：使用 **RelWithDebInfo**
- 生产发布：使用 **MinSizeRel**（默认）
- 深度调试：使用 **Debug**（注意Flash限制）

## 🐛 调试技巧

### 1. 在VSCode中调试

1. 编译RelWithDebInfo版本
2. 连接JLink调试器
3. 在VSCode中选择 "Run and Debug"
4. 选择 "jlink (micoair_h743) - Release" 配置
5. 按F5开始调试

### 2. 设置断点

在代码中可以直接点击行号左侧设置断点，或使用：
```cpp
// 在代码中添加硬件断点
__asm__ volatile("bkpt 0");
```

### 3. 查看变量

- **局部变量**：在 Variables 面板自动显示
- **全局变量**：在 Watch 面板手动添加
- **寄存器**：在 Registers 面板查看

### 4. GDB命令

在Debug Console中可以直接使用GDB命令：
```gdb
# 查看当前线程
info threads

# 查看调用栈
bt

# 查看内存
x/16x 0x20000000

# 打印变量
print variable_name
```

## 🔄 快速切换构建类型

创建这些命令别名（添加到 ~/.bashrc）：

```bash
# PX4编译别名
alias px4_release='export PX4_CMAKE_BUILD_TYPE=Release'
alias px4_debug='export PX4_CMAKE_BUILD_TYPE=RelWithDebInfo'
alias px4_debug_full='export PX4_CMAKE_BUILD_TYPE=Debug'
alias px4_minsize='unset PX4_CMAKE_BUILD_TYPE'  # 默认MinSizeRel

# 清理并编译
alias px4_clean='rm -rf build/micoair_h743_default'
alias px4_build='make micoair_h743_default'
```

使用示例：
```bash
px4_debug      # 设置为RelWithDebInfo
px4_clean      # 清理
px4_build      # 编译
```

## ❓ 常见问题

### Q1: Debug版本编译失败，提示Flash不足？

**A:** Debug版本太大，超出Flash限制。解决方法：
1. 使用 **RelWithDebInfo** 代替完整的Debug
2. 或者禁用一些不需要的模块（参考 boards/px4/fmu-v5/debug.px4board）

### Q2: 调试时无法看到变量值，显示 <optimized out>？

**A:** 这是因为优化级别太高。解决方法：
- 使用Debug版本（-O0）而不是RelWithDebInfo（-O2）
- 或者在需要调试的特定文件中关闭优化：
  ```cmake
  # 在CMakeLists.txt中
  set_source_files_properties(your_file.cpp PROPERTIES COMPILE_FLAGS "-O0")
  ```

### Q3: 如何只对某个模块编译Debug版本？

**A:** 在模块的CMakeLists.txt中添加：
```cmake
# src/modules/gg_imu_logger/CMakeLists.txt
px4_add_module(
    MODULE modules__gg_imu_logger
    MAIN gg_imu_logger
    COMPILE_FLAGS
        -O0          # 无优化
        -g3          # 最详细的调试信息
    SRCS
        gg_imu_logger.cpp
    DEPENDS
        px4_work_queue
)
```
