## 二、关键性能指标对比

### 2.1 `get_dt_ekf_avg()` vs `perf_counter`

#### 两个指标的本质区别

| 指标 | `get_dt_ekf_avg()` | `perf_counter(_ekf_update_perf)` |
|------|-------------------|----------------------------------|
| **测量对象** | IMU 数据到达间隔 | EKF 算法执行时间 |
| **物理意义** | 滤波器更新周期（输入频率） | 计算负载（CPU 耗时） |
| **典型值** | 10 ms (100Hz) | 0.27 ms |
| **代码位置** | `ekf.cpp:152-169` | `EKF2.cpp:802-805` |
| **计算方式** | IMU delta_t 的低通滤波 | perf_set_elapsed 统计 |
| **用途** | 确定滤波器运行频率 | 评估性能/查找瓶颈 |

#### `get_dt_ekf_avg()` 计算逻辑

```cpp
// src/modules/ekf2/EKF/ekf.cpp:152-169
const float filter_update_s = 1e-6f * _params.ekf2_predict_us;
const float input = math::constrain(0.5f * (imu_sample_delayed.delta_vel_dt + imu_sample_delayed.delta_ang_dt),
                                    0.5f * filter_update_s,
                                    2.f * filter_update_s);

if (_is_first_imu_sample) {
    _dt_ekf_avg = input;  // 首次直接赋值
} else {
    _dt_ekf_avg = 0.99f * _dt_ekf_avg + 0.01f * input;  // 低通滤波
}
```

**特点**:
- 取角度积分时间和速度积分时间的平均值
- 使用系数0.99的低通滤波器平滑
- 反映IMU数据实际到达频率

#### `perf_counter` 统计原理

```cpp
// src/modules/ekf2/EKF2.cpp:802-805
const hrt_abstime ekf_update_start = hrt_absolute_time();

if (_ekf.update()) {
    perf_set_elapsed(_ekf_update_perf, hrt_elapsed_time(&ekf_update_start));
```

**统计内容**:
- `event_count`: 总执行次数
- `time_total`: 累计总时间
- `avg`: 平均耗时 = total / count
- `min/max`: 最小/最大单次耗时
- `rms`: 均方根偏差（抖动）

**性能评估**:
```
EKF dt: 0.0100s → IMU以稳定的100Hz提供数据
avg: 274.58us → 每次更新仅占2.7%的可用时间 (274/10000)
max: 758us → 最坏情况也只占7.6%的周期
```

结论: EKF性能健康，CPU负载很低

## 三、IMU数据频率架构

### 3.1 完整数据流向

```
原始传感器 (gyro/accel)
   │  1000-8000 Hz (取决于 IMU 芯片)
   ↓
vehicle_imu 模块
   │  积分 + 降采样
   │  IMU_INTEG_RATE = 200 (默认)
   │  ↓
   │  200 Hz
   ↓
EKF2 订阅
   │  每 2 个样本使用 1 个
   │  EKF2_PREDICT_US = 10000 (默认)
   │  ↓
   │  100 Hz
   ↓
姿态/位置输出
   │  Output Predictor
   │  ↓
   │  200 Hz (姿态发布)
```

### 3.2 为什么姿态发布是200Hz而EKF更新是100Hz?

#### Output Predictor 机制

**代码位置**: `EKF2.cpp:750-751`

```cpp
// push imu data into estimator
_ekf.setIMUData(imu_sample_new);
PublishAttitude(now); // publish attitude immediately (uses quaternion from output predictor)
```

**关键**: 注释说明 "uses quaternion from output predictor"

#### 调用链

```
EKF2.cpp:751: PublishAttitude(now)
    ↓
EKF2.cpp:1042: _ekf.getQuaternion().copyTo(att.q)
    ↓
estimator_interface.h:252: return _output_predictor.getQuaternion()
    ↓
output_predictor.h:96: return _output_new.quat_nominal
```

#### 双频率设计原因

```
Output Predictor (200Hz)    ←→    EKF Core (100Hz)
      ↓                                  ↓
  快速预测                           精确融合
  使用最新IMU                        使用延迟IMU + 多传感器
  低延迟输出 (<1ms)                  高精度估计
      ↑                                  ↓
      └──────── correctOutputStates ─────┘
              (用EKF结果校正预测误差)
```

**优势**:
- ✅ 降低计算负载: EKF算法复杂，100Hz节省50% CPU
- ✅ 满足控制需求: 200Hz姿态输出足够飞控使用
- ✅ 低延迟输出: 姿态延迟<1ms，控制响应快

**数据转换细节**:

```cpp
// VotedSensorsUpdate: delta → rate

Vector3f accel_data = Vector3f{imu_report.delta_velocity} * accel_dt_inv;

const float gyro_dt_inv = 1.e6f / (float)imu_report.delta_angle_dt;
```

## 六、EKF2 核心架构设计

### 6.1 双层架构概览

```
┌──────────────────────────────────────────────────────────────┐
│  EKF2 = 双层架构 (互补滤波器 + 固定延迟平滑器)                │
├──────────────────────────────────────────────────────────────┤
│                                                                │
│  【底层】EKF Core - 最优估计器 (100Hz, 高精度, 有延迟)       │
│  ════════════════════════════════════════════════════════════ │
│                                                                │

│     │   ├─ GPS融合 → 修正位置/速度                            │

│                                                                │

│  ════════════════════════════════════════════════════════════ │
│                                                                │
│  ③ 互补滤波 (200Hz)                                           │
│     calculateOutputStates(imu_sample)                          │
│     • 偏差修正: Δθ = Δθ_meas - bias*dt + _delta_angle_corr   │
│     • 姿态积分: q = q_old ⊗ Δq                                │
│     • 速度积分: v = v_old + R*Δv + g*dt                       │
│     • 位置积分: p = p_old + (v_old+v_new)*dt/2 (梯形)        │
│                                                                │
│  ④ 实时发布 (200Hz)                                           │
│     PublishAttitude(_output_new.quat_nominal)                 │

│                                                                │

```

### 6.2 核心设计思想

**一句话总结**:
> 用历史的多传感器融合数据估计当前的误差，通过反馈校正补偿到当前IMU测量值，输出低延迟高精度的估计值

**设计目标**:
- 精度: 多传感器卡尔曼融合
- 延迟: Output Predictor 实时输出
- 鲁棒: 互补滤波器自动校正漂移

## 七、Output Predictor 详解

### 7.1 calculateOutputStates() - 实时预测

**代码位置**: `output_predictor.cpp:178-265`

**执行频率**: 200Hz (每次IMU到达)

**关键步骤**:

```cpp
void OutputPredictor::calculateOutputStates(const uint64_t time_us,
    const Vector3f &delta_angle, const float delta_angle_dt,
    const Vector3f &delta_velocity, const float delta_velocity_dt)
{
    // Step 1: 时间管理
    const float dt = (time_us - _time_last_update_states_us) * 1e-6f;
    _dt_update_states_avg = 0.8f * _dt_update_states_avg + 0.2f * dt;

    // Step 2: 偏差修正 (使用上次EKF计算的值)
    const Vector3f delta_angle_bias_scaled = _gyro_bias * delta_angle_dt;
    const Vector3f delta_angle_corrected = delta_angle - delta_angle_bias_scaled + _delta_angle_corr;
    //                                                                              ^^^^^^^^^^^^^^^^^^
    //                                                                              EKF反馈校正项

    const Vector3f delta_velocity_corrected = delta_velocity - _accel_bias * delta_velocity_dt;

    // Step 3: 姿态更新 (四元数积分)
    const Quatf dq(AxisAnglef{delta_angle_corrected});
    _output_new.quat_nominal = _output_new.quat_nominal * dq;
    _output_new.quat_nominal.normalize();

    // Step 4: 速度更新
    Vector3f delta_vel_earth = _R_to_earth_now * delta_velocity_corrected;
    delta_vel_earth(2) += CONSTANTS_ONE_G * delta_velocity_dt;  // 重力补偿
    _output_new.vel += delta_vel_earth;

    // Step 5: 位置更新 (梯形积分)
    const Vector3f vel_avg = (_output_new.vel + vel_last);
    _output_new.pos += vel_avg * (delta_velocity_dt * 0.5f);

    // Step 6: IMU偏移补偿
    const Vector3f ang_rate = delta_angle_corrected / delta_angle_dt;
    _vel_imu_rel_body_ned = _R_to_earth_now * (ang_rate % _imu_pos_body);
}
```

**数学公式**:

姿态:
$$q_{k+1} = q_k \otimes \Delta q, \quad \Delta q = \exp(\frac{\Delta\theta}{2})$$

速度:
$$v_{k+1} = v_k + R_b^n \cdot \Delta v + g \cdot dt$$

位置 (梯形积分):
$$p_{k+1} = p_k + \frac{v_k + v_{k+1}}{2} \cdot dt$$

### 7.2 correctOutputStates() - EKF校正

**代码位置**: `output_predictor.cpp:267-356`

**执行频率**: 100Hz (每次EKF更新后)

**关键步骤**:

```cpp
void OutputPredictor::correctOutputStates(const uint64_t time_delayed_us,
    const Quatf &quat_state, const Vector3f &vel_state, const LatLonAlt &gpos_state,
    const Vector3f &gyro_bias, const Vector3f &accel_bias)
{
    // Step 1: 更新偏差估计
    _gyro_bias = gyro_bias;
    _accel_bias = accel_bias;

    // Step 2: 存储当前预测到Buffer
    _output_buffer.push(_output_new);

    // Step 3: 取出延迟时刻的预测状态
    const outputSample &output_delayed = _output_buffer.get_oldest();

    // Step 4: 计算姿态误差 (同一时刻比较！)
    const Quatf q_error = quat_state.inversed() * output_delayed.quat_nominal;
    //                    ^^^^^^^^^^             ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
    //                    EKF融合值(t-200ms)     Predictor预测值(t-200ms)

    // Step 5: 转为角度误差
    const Vector3f delta_ang_error = 2 * [q_error.x, q_error.y, q_error.z];

    // Step 6: 计算校正增益 (自适应)
    const float time_delay = (time_latest_us - time_delayed_us) * 1e-6f;
    const float att_gain = 0.5f * _dt_update_states_avg / time_delay;

    // Step 7: 计算姿态校正项
    _delta_angle_corr = delta_ang_error * att_gain;

    // Step 8: 校正Buffer中的速度和位置 (批量修正)
    for (all states in buffer) {
        state.vel += vel_correction;
        state.pos += pos_correction;
    }

    // Step 9: 用校正后的值更新_output_new
    _output_new = _output_buffer.get_newest();
}
```

**控制增益**:

$$K_{att} = \frac{0.5 \cdot dt_{update}}{t_{delay}} = \frac{0.5 \times 0.005}{0.2} = 0.0125$$

阻尼比设计为 ~0.7，保证稳定收敛。

## 八、互补滤波器反馈循环

### 8.1 完整时间线

```
时间线 (稳定运行状态):
───────────────────────────────────────────────────────────────

t=0ms:  【IMU#1 到达】
        ├─ calculateOutputStates (使用 bias[-1], corr[-1])
        └─ 发布姿态 #1

t=5ms:  【IMU#2 到达】
        ├─ calculateOutputStates (使用 bias[-1], corr[-1])
        ├─ 发布姿态 #2
        └─ EKF update() ★
           └─ correctOutputStates()
              └─ 更新 bias[0], corr[0]

t=10ms: 【IMU#3 到达】
        ├─ calculateOutputStates (使用 bias[0], corr[0]) ← 新值
        └─ 发布姿态 #3

t=15ms: 【IMU#4 到达】
        ├─ calculateOutputStates (使用 bias[0], corr[0])
        ├─ 发布姿态 #4
        └─ EKF update()
           └─ 更新 bias[1], corr[1]

循环重复...
```

### 8.2 校正值使用模式

**每个周期（10ms）**:
1. 第1次发布 (t=0,10,20...): 使用 **5-10ms前** 更新的值
2. 第2次发布 (t=5,15,25...): 使用 **10-15ms前** 的值 (最旧)
3. EKF更新后: 计算新的 bias 和 corr

**校正值生命周期**:
- 计算频率: 100Hz (每10ms)
- 使用次数: 每个值使用2次
- 生效延迟: 5ms (从计算到首次使用)
- 老化范围: 5ms ~ 15ms

### 9.2 为什么需要200ms延迟？

**传感器延迟对比**:

| 传感器 | 固有延迟 | 参数 |
|--------|----------|------|
| IMU | 0ms | - |
| 磁力计 | 0-20ms | EKF2_MAG_DELAY |
| 气压计 | 0-20ms | EKF2_BARO_DELAY |
| 光流 | ~50ms | EKF2_OF_DELAY |
| 视觉里程计 | 50-100ms | EKF2_EV_DELAY |
| **GPS** | **110ms** | **EKF2_GPS_DELAY** |
| 安全裕度 | +90ms | - |
| **总计** | **200ms** | **EKF2_DELAY_MAX** |

**时间对齐的必要性**:

```
问题: GPS标记为t=0的观测，在t=110ms才到达

t=0ms:   IMU测量 → 存入Buffer[0]
         飞机实际位置: [100, 50, 10] m

t=110ms: GPS到达，报告位置 [100.5, 50.2, 10.1] m (t=0时刻)
         需要找到t=0的IMU数据进行融合
         └─ 从Buffer[0]取出 ✓

t=200ms: EKF处理
         • IMU(t=0) + GPS(t=0) → 时间对齐
         • 卡尔曼融合 → 最优估计
```

如果Buffer太小，历史数据会被覆盖，无法融合！

### 9.3 三个关键四元数

**时刻 t=200ms 时**:

| 四元数 | 时间点 | 来源 | 精度 | 延迟 | 用途 |
|--------|--------|------|------|------|------|
| `_state.quat_nominal` | t=0ms | EKF多传感器融合 | ⭐⭐⭐⭐⭐ | 200ms | 作为参考 |
| `output_delayed.quat` | t=0ms | 纯陀螺积分(Buffer) | ⭐⭐⭐ | 200ms | 误差比较 |
| `_output_new.quat` | t=200ms | 陀螺积分+EKF校正 | ⭐⭐⭐⭐ | 0ms | **发布输出** |

**关键理解**:
- ✅ 比较的是**同一时刻**的两个状态 (时间对齐)
- ✅ 发布的是**最新时刻**的预测 (低延迟)
- ✅ 校正值**5ms后**生效 (快速反馈)

## 十、数学原理

### 10.1 状态预测方程

**姿态预测**:

```cpp
// ekf.cpp:238-249
const Vector3f delta_ang_bias_scaled = getGyroBias() * imu_delayed.delta_ang_dt;
Vector3f corrected_delta_ang = imu_delayed.delta_ang - delta_ang_bias_scaled;
corrected_delta_ang -= _R_to_earth.transpose() * _earth_rate_NED * imu_delayed.delta_ang_dt;

const Quatf dq(AxisAnglef{corrected_delta_ang});
_state.quat_nominal = (_state.quat_nominal * dq).normalized();
```

$$
\begin{align}
\omega_{corrected} &= \omega_{meas} - b_{gyro} - R_b^n \cdot \omega_{earth} \\
\Delta q &= \exp(\frac{\Delta\theta}{2}) \\
q_{k+1} &= q_k \otimes \Delta q
\end{align}
$$

**速度预测**:

```cpp
// ekf.cpp:251-266
const Vector3f corrected_delta_vel_ef = _R_to_earth * corrected_delta_vel;
const Vector3f vel_last = _state.vel;
_state.vel += corrected_delta_vel_ef;

const Vector3f gravity_acceleration(0.f, 0.f, CONSTANTS_ONE_G);
const Vector3f coriolis_acceleration = -2.f * _earth_rate_NED.cross(vel_last);
_state.vel += (gravity_acceleration + coriolis_acceleration) * dt;
```

$$v_{k+1} = v_k + R_b^n \cdot \Delta v + (g - 2\omega_{ie} \times v_k) \cdot dt$$

**位置预测** (梯形积分):

```cpp
// ekf.cpp:268-270
_gpos += (vel_last + _state.vel) * imu_delayed.delta_vel_dt * 0.5f;
```

$$p_{k+1} = p_k + \frac{v_k + v_{k+1}}{2} \cdot dt$$

### 10.2 协方差预测

**代码位置**: `covariance.cpp:113-140`

```cpp
void Ekf::predictCovariance(const imuSample &imu_delayed)
{
    const float dt = 0.5f * (imu_delayed.delta_vel_dt + imu_delayed.delta_ang_dt);

    // 过程噪声
    const float gyro_var = sq(_params.ekf2_gyr_noise);
    Vector3f accel_var = sq(_params.ekf2_acc_noise);

    // 协方差传播 (自动求导生成的代码)
    P = sym::PredictCovariance(_state.vector(), P,
                               imu_delayed.delta_vel / dt, accel_var,
                               imu_delayed.delta_ang / dt, gyro_var,
                               dt);

    // 添加过程噪声
    P(gyro_bias) += sq(dt * _params.ekf2_gyr_b_noise);
    P(accel_bias) += sq(dt * _params.ekf2_acc_b_noise);
}
```

$$P_{k+1} = F \cdot P_k \cdot F^T + G \cdot Q \cdot G^T$$

其中:
- $F$: 状态转移雅可比矩阵
- $Q$: 过程噪声协方差
- $G$: 噪声映射矩阵

### 10.3 测量更新方程

**代码位置**: `ekf_helper.cpp:736-743`

```cpp
void Ekf::fuse(const VectorState &K, float innovation)
{
    // 姿态更新
    Quatf delta_quat(AxisAnglef(K.slice<quat_dof>(quat_idx) * (-innovation)));
    _state.quat_nominal = delta_quat * _state.quat_nominal;
    _state.quat_nominal.normalize();

    // 速度、位置、偏差等更新
    _state.vel -= K.slice<vel_dof>(vel_idx) * innovation;
    _state.pos -= K.slice<pos_dof>(pos_idx) * innovation;
    _state.gyro_bias -= K.slice<gyro_bias_dof>(gyro_bias_idx) * innovation;
    // ...
}
```

**卡尔曼增益**:

$$K = P \cdot H^T / (H \cdot P \cdot H^T + R)$$

**状态更新**:

$$x = x + K \cdot (z - h(x))$$

**协方差更新** (Joseph形式):

$$P = (I - K \cdot H) \cdot P \cdot (I - K \cdot H)^T + K \cdot R \cdot K^T$$

## 十一、性能分析

### 11.1 延迟分析

**闭环总延迟**:

```
误差产生(t=0) → EKF检测(t=200) → 校正生效(t=205)

总延迟 = 200 + 5 = 205ms
```

**但实际影响很小**:
- 陀螺漂移速率: ~0.001 rad/s² (温漂)
- 205ms内的额外误差: 0.001 × 0.205 = 0.0002 rad ≈ 0.01°
- 完全可以忽略

### 11.2 收敛性能

**增益设计**:

$$K = 0.025 \quad (\text{典型值})$$

**收敛速度**:

$$\text{时间常数} \quad \tau = \frac{-dt}{\ln(1-K)} = \frac{-0.01}{\ln(0.975)} \approx 0.4s$$

**99%收敛时间**: $5\tau \approx 2s$

### 11.3 实测跟踪误差

典型值 (可通过 `estimator_status.output_tracking_error` 查看):
- 姿态误差: < 0.01 rad (< 0.6°)
- 速度误差: < 0.1 m/s
- 位置误差: < 1 m

## 十二、关键设计要点总结

### 12.1 核心思想

```
┌──────────────────────────────────────────────────────────────┐
│                                                                │
│  用过去的最优真相，校正现在的快速猜测                         │
│                                                                │
│  Past Optimal Truth  →  Corrects  →  Present Fast Guess       │
│                                                                │
└──────────────────────────────────────────────────────────────┘
```

### 12.2 解决的矛盾

1. **精度 vs 延迟**:
   - EKF融合慢但准 (200ms延迟)
   - Predictor快但会漂移 (<1ms延迟)
   - 解决: 互补滤波器结合两者优点

2. **频率 vs 计算量**:
   - 控制需要200Hz姿态
   - EKF计算重 (274μs/次)
   - 解决: 多速率系统 (100Hz EKF + 200Hz Predictor)

3. **传感器延迟 vs 实时性**:
   - GPS延迟110ms
   - 控制需要实时
   - 解决: 固定延迟平滑器 + 前向预测

### 12.3 关键技术

- ✅ **Fixed-Lag Smoother**: 固定延迟卡尔曼平滑
- ✅ **Complementary Filter**: 互补滤波器
- ✅ **Multi-Rate System**: 多速率系统
- ✅ **Feedback Control**: 比例反馈控制
- ✅ **Time Alignment**: 时间戳对齐

### 12.4 工程权衡

| 方面 | 选择 | 原因 |
|------|------|------|
| EKF频率 | 100Hz | 平衡精度和CPU负载 |
| 输出频率 | 200Hz | 满足控制回路需求 |
| Buffer深度 | 200ms | 容纳GPS最大延迟 |
| 校正增益 | 0.025 | 保证稳定性(阻尼0.7) |

## 十四、常见问题

### Q1: 为什么用200ms前的数据计算校正值？

**A**: 这不是低频更新！
- 校正值每10ms更新一次 (100Hz)
- 比较200ms前的**同一时刻**是为了时间对齐
- 目的是提取纯粹的预测误差，不包含运动变化
- 校正值5ms后就生效，实际延迟很短

### Q2: Output Predictor会不会漂移？

**A**: 会轻微漂移，但会被EKF持续校正
- 短期(<1s): 陀螺积分精度高，漂移小
- 长期(>1s): EKF校正抵消漂移
- 稳态误差: <0.6° (实测)

### Q3: 如果快速机动会怎样？

**A**: 不影响！
- 比较的是同一时刻的状态，消除运动影响
- 只提取漂移误差，不包含机动
- 快速翻滚时，校正值保持很小

### Q4: 为什么姿态发布200Hz而EKF才100Hz？

**A**: Output Predictor在每次IMU到达时预测并发布
- Output Predictor: 200Hz实时预测
- EKF: 100Hz精确融合
- 互补设计: 既快又准
