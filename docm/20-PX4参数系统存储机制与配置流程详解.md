# 20-PX4参数系统存储机制与配置流程详解
## 从编译配置到运行时参数修改的完整流程分析

---

## 1. 概述

本文档详细梳理PX4参数系统的存储机制、加载流程、修改方法，以及各种配置文件的作用和优先级。以MicoAir H743飞控为例，说明参数如何从编译时配置到运行时修改。

### 核心问题
1. `rc.board_defaults` 是否被硬编码到固件？
2. SD卡上修改哪个文件可以永久改变参数？
3. QGC修改参数后存到哪里？为什么需要重启？
4. 参数存储位置如何决定（Flash还是SD卡）？
5. 所有操作的源码位置？

## 2. 参数存储位置的决定机制

### 2.1 三种存储后端

PX4参数系统支持三种存储后端：

| 存储后端 | 位置 | 使用场景 | 编译时配置 |
|---------|------|---------|-----------|
| **SD卡存储** | `/fs/microsd/params` | 标准飞控（有SD卡） | 不定义`FLASH_BASED_PARAMS` |
| **Flash存储** | MCU内部Flash | 无SD卡飞控（如Omnibus） | 定义`FLASH_BASED_PARAMS` |
| **FRAM存储** | `/fs/mtd_params` | 带FRAM的飞控（如Pixhawk） | 板级配置 |

### 2.2 MicoAir H743的存储配置

**文件**: `boards/micoair/h743/default.px4board`

**第10行**: 参数文件路径配置
```config
CONFIG_BOARD_PARAM_FILE="/fs/microsd/params"
```

**文件**: `boards/micoair/h743/src/init.c`

**第187-202行**: Flash存储配置（已注释，表示未启用）
```c
// TODO：internal flash store parameters
#if defined(FLASH_BASED_PARAMS)
	static sector_descriptor_t params_sector_map[] = {
		{15, 128 * 1024, 0x081E0000},  // Flash Sector 15, 128KB
		{0, 0, 0},
	};

	/* Initialize the flashfs layer to use heap allocated memory */
	int result = parameter_flashfs_init(params_sector_map, NULL, 0);

	if (result != OK) {
		syslog(LOG_ERR, "[boot] FAILED to init params in FLASH %d\n", result);
		led_on(LED_RED);
	}
#endif
```

**结论**：
- MicoAir H743 **未定义** `FLASH_BASED_PARAMS`
- 参数存储位置：`/fs/microsd/params` **(SD卡)**
- 备份位置：`/fs/microsd/params_backup` （如果启用）

## 3. rc.board_defaults的作用与编译流程

### 3.1 rc.board_defaults是否被硬编码？

**答案：是的，被编译进固件的ROMFS中**

**文件**: `ROMFS/CMakeLists.txt`

**第170-202行**: 板级默认参数文件的编译流程
```cmake
# optional board defaults: rc.board_defaults
set(board_rc_file "rc.board_defaults")
if(EXISTS "${PX4_BOARD_DIR}/init/${board_rc_file}")
	file(RELATIVE_PATH rc_file_relative ${PX4_SOURCE_DIR} ${PX4_BOARD_DIR}/init/${board_rc_file})
	message(STATUS "ROMFS:  Adding ${rc_file_relative} -> /etc/init.d/${board_rc_file}")

	add_custom_command(
		OUTPUT
			${romfs_gen_root_dir}/init.d/${board_rc_file}
			${board_rc_file}.stamp
		COMMAND ${CMAKE_COMMAND} -E copy_if_different
			${PX4_BOARD_DIR}/init/${board_rc_file}    # ← 源文件
			${romfs_gen_root_dir}/init.d/${board_rc_file}  # ← 目标位置
		COMMAND ${CMAKE_COMMAND} -E touch ${board_rc_file}.stamp
		DEPENDS
			${PX4_BOARD_DIR}/init/${board_rc_file}
		)
	list(APPEND extras_dependencies ${board_rc_file}.stamp)
endif()
```

**编译流程**：
```
boards/micoair/h743/init/rc.board_defaults
  ↓ (编译时复制)
build/micoair_h743_default/romfs/init.d/rc.board_defaults
  ↓ (打包进ROMFS)
固件中的 ROMFS 文件系统
  ↓ (运行时挂载到)
/etc/init.d/rc.board_defaults
```

**结论**：
- `rc.board_defaults` **被硬编码到固件中**
- 存储在ROMFS（只读文件系统）
- 修改后需要**重新编译固件**才能生效

### 3.2 rc.board_defaults的加载时机

**文件**: `ROMFS/px4fmu_common/init.d/rcS`

**第209-218行**: rc.board_defaults加载
```bash
#
# Optional board defaults: rc.board_defaults
#
set BOARD_RC_DEFAULTS ${R}etc/init.d/rc.board_defaults
if [ -f $BOARD_RC_DEFAULTS ]
then
	echo "Board defaults: ${BOARD_RC_DEFAULTS}"
	. $BOARD_RC_DEFAULTS  # ← 执行脚本，设置默认参数
fi
unset BOARD_RC_DEFAULTS
```

**加载顺序**：
```
1. param import (从SD/Flash加载用户参数)
2. rc.board_arch_defaults (架构级默认)
3. rc.board_defaults (板级默认)  ← 这里！
4. rc.autostart (机架配置)
```

**作用**：
- 设置板级特定的默认值
- 只影响**未被用户修改过的参数**
- 使用 `param set-default` 命令

### 4.2 参数层次结构

PX4参数系统采用**多层结构**，后加载的层覆盖前面的层：

**文件**: `src/lib/parameters/parameters.cpp`

**第103-105行**: 参数层次定义
```cpp
static ConstLayer firmware_defaults;                    // 层1: 固件默认值
static DynamicSparseLayer runtime_defaults{&firmware_defaults};  // 层2: 运行时默认值
DynamicSparseLayer user_config{&runtime_defaults};      // 层3: 用户配置
```

**层次说明**：
```
层1: firmware_defaults (ConstLayer)
  ├─ 来源: 代码中的 PARAM_DEFINE_XXX
  ├─ 示例: PARAM_DEFINE_INT32(SENS_IMU_MODE, 1);
  ├─ 特点: 编译时确定，不可修改
  └─ 位置: src/modules/*/sensor_params.c 等

层2: runtime_defaults (DynamicSparseLayer)
  ├─ 来源: param set-default 命令
  ├─ 示例: rc.board_defaults 中的 "param set-default BAT1_V_DIV 21.2"
  ├─ 特点: 启动时设置，仅当用户未修改时生效
  └─ 位置: 内存中

层3: user_config (DynamicSparseLayer)
  ├─ 来源: param set 命令 或 QGC修改
  ├─ 示例: "param set SENS_IMU_MODE 0"
  ├─ 特点: 用户显式修改的值，优先级最高
  └─ 位置: 持久化到SD卡或Flash
```

### 4.3 参数查找逻辑

**文件**: `src/lib/parameters/parameters.cpp`

**第286-318行**: param_get函数
```cpp
int param_get(param_t param, void *val)
{
	if (!handle_in_range(param)) {
		PX4_ERR("get: param %" PRId16 " invalid", param);
		return PX4_ERROR;
	}

	if (val) {
		// 从最高层（user_config）开始查找
		auto retrieve_value = user_config.get(param);
		//                    ↑
		//     如果user_config没有，会自动查找下一层runtime_defaults
		//     如果runtime_defaults也没有，会查找firmware_defaults

		switch (param_type(param)) {
		case PARAM_TYPE_INT32:
			memcpy(val, &retrieve_value.i, sizeof(retrieve_value.i));
			return PX4_OK;

		case PARAM_TYPE_FLOAT:
			memcpy(val, &retrieve_value.f, sizeof(retrieve_value.f));
			return PX4_OK;
		}
	}

	return PX4_ERROR;
}
```

**查找顺序**：
```
param_get("SENS_IMU_MODE")
  ↓
1. 查找 user_config (用户修改的值)
   ├─ 找到 → 返回用户值 (如: 0)
   └─ 未找到 ↓
2. 查找 runtime_defaults (启动脚本设置的默认值)
   ├─ 找到 → 返回默认值 (如: rc.board_defaults中的1)
   └─ 未找到 ↓
3. 查找 firmware_defaults (代码中定义的默认值)
   └─ 返回固件默认值 (如: PARAM_DEFINE_INT32(SENS_IMU_MODE, 1))
```

### 6.2 /fs/microsd/params 文件格式

**格式**：BSON (Binary JSON)

**结构**：
```
[BSON Document]
├── Header
│   ├── Magic: 0x67736f62 ("bson")
│   ├── Version: 1
│   └── CRC32
├── Parameters
│   ├── "SENS_IMU_MODE": (int32) 0
│   ├── "EKF2_MULTI_IMU": (int32) 2
│   ├── "BAT1_V_DIV": (float) 21.2
│   └── ... (所有被修改过的参数)
└── Footer
```

**查看参数文件内容**：
```bash
# NSH命令行
nsh> bsondump /fs/microsd/params

# 输出示例：
# {
#   "SENS_IMU_MODE": 0,
#   "EKF2_MULTI_IMU": 2,
#   "BAT1_V_DIV": 21.2,
#   ...

```

### 6.3 直接修改SD卡参数文件

**方法1: 通过NSH命令（推荐）**
```bash
nsh> param set SENS_IMU_MODE 0
nsh> param set EKF2_MULTI_IMU 2
nsh> param save  # ← 保存到 /fs/microsd/params
nsh> reboot
```

**方法2: 直接编辑SD卡文件（不推荐）**

BSON是二进制格式，**不能直接用文本编辑器编辑**。

如果要手动修改，需要：
1. 导出为文本格式
2. 修改
3. 重新导入

```bash
# 导出为文本
nsh> param export /fs/microsd/params.txt

# 将SD卡插到电脑，编辑 params.txt
# 格式: 参数名<空格>值
SENS_IMU_MODE 0
EKF2_MULTI_IMU 2
BAT1_V_DIV 21.2

# 重新插入飞控，导入
nsh> param import /fs/microsd/params.txt
nsh> param save
nsh> reboot
```

**方法3: 通过/fs/microsd/etc/extras.txt（最灵活）**

创建 `/fs/microsd/etc/extras.txt` 文件：
```bash
#!/bin/sh
# 这个脚本在每次启动时执行

param set SENS_IMU_MODE 0
param set EKF2_MULTI_IMU 2
```

**优点**：
- 文本文件，易于编辑
- 每次启动自动执行
- 不会被参数重置影响

**加载位置**：

**文件**: `ROMFS/px4fmu_common/init.d/rcS`

**第220-229行**：
```bash

then
	echo "Board additional init: ${BOARD_RC_ADDITIONAL_INIT}"
```

```
  ↓

  ↓
```

### 7.2 自动保存机制

**文件**: `src/lib/parameters/autosave.cpp`

**第79-130行**: ParamAutosave实现
```cpp
void ParamAutosave::Run()
{
	if (!_param_autosave_enable.get()) {
		// 如果禁用自动保存，直接返回
		ScheduleDelayed(1_s);
		return;
	}

	bool disabled = true;

	// 检查是否有未保存的参数
	if (param_get_used_count() > 0) {
		for (param_t param = 0; param < param_count(); param++) {
			if (param_value_unsaved(param)) {  // ← 检查unsaved标志
				disabled = false;
				break;
			}
		}
	}

	if (disabled) {
		ScheduleDelayed(1_s);
		return;
	}

	// 延迟一段时间再保存（等待连续修改）
	const hrt_abstime last_change = param_get_last_used_change_timestamp();
	static constexpr hrt_abstimerate_limit = 2_s;

	if (last_change > 0 && (hrt_elapsed_time(&last_change) > rate_limit)) {
		// 执行保存
		int ret = param_save_default(false);  // ← 保存到默认文件

		if (ret == 0) {
			PX4_DEBUG("parameters saved");
		}
	}

	ScheduleDelayed(100_ms);
}
```

**关键点**：
- 自动保存延迟：2秒（等待连续修改完成）
- 检查周期：100ms
- 非阻塞保存（false参数）

## 8. 参数保存的核心代码

### 8.1 param_save_default 函数

**文件**: `src/lib/parameters/parameters.cpp`

**第785-879行**: 参数保存实现
```cpp
int param_save_default(bool blocking)
{
	PX4_DEBUG("param_save_default");

	// 获取互斥锁
	if (blocking) {
		pthread_mutex_lock(&file_mutex);
	} else {
		if (pthread_mutex_trylock(&file_mutex) != 0) {
			return -EWOULDBLOCK;
		}
	}

	int res = PX4_ERROR;
	const char *filename = param_get_default_file();  // ← 获取参数文件路径

	if (filename) {
		// ========== SD卡或文件系统存储 ==========
		static constexpr int MAX_ATTEMPTS = 3;

		for (int attempt = 1; attempt <= MAX_ATTEMPTS; attempt++) {
			// 打开文件（覆盖模式）
			int fd = ::open(filename, O_WRONLY | O_CREAT | O_TRUNC, PX4_O_MODE_666);
			//                        ↑ O_TRUNC: 清空原文件内容

			if (fd > -1) {
				// 导出参数到文件
				res = param_export_internal(fd, nullptr);  // ← 写入BSON格式
				::close(fd);

				if (res == PX4_OK) {
					// 重新打开验证
					int fd_verify = ::open(filename, O_RDONLY, PX4_O_MODE_666);
					res = param_verify(fd_verify);
					::close(fd_verify);
				}
			}

			if (res == PX4_OK) {
				break;
			} else {
				PX4_ERR("parameter export to %s failed (%d) attempt %d",
				        filename, res, attempt);
				px4_usleep(10000);
			}
		}

	} else {
		// ========== Flash存储 ==========
		res = flash_param_save(nullptr);  // ← 保存到Flash
	}

	if (res == PX4_OK) {
		params_unsaved.reset();  // ← 清除unsaved标志

		// 保存备份文件
		if (param_backup_file) {
			int fd_backup_file = ::open(param_backup_file, O_WRONLY | O_CREAT | O_TRUNC, ...);
			if (fd_backup_file > -1) {
				param_export_internal(fd_backup_file, nullptr);
				::close(fd_backup_file);
			}
		}
	}

	pthread_mutex_unlock(&file_mutex);
	return res;
}
```

**关键点**：
- 文件名从 `param_get_default_file()` 获取（在rcS中由`param select`设置）
- 使用 `O_TRUNC` 标志，**完全覆盖原文件**
- 最多尝试3次（防止SD卡写入失败）
- 同时更新备份文件（如果配置）

### 8.2 存储位置的决定逻辑

**文件**: `src/lib/parameters/parameters.cpp`

**第749-752行**: param_get_default_file函数

**第722-747行**: param_set_default_file函数

## 9. QGC修改参数后为什么需要重启？

### 9.1 参数的生效时机

参数分为两类：

#### 类型1: 运行时生效的参数
```cpp
// 示例: MC_ROLL_P (多旋翼横滚P增益)
class MulticopterAttitudeControl : public ModuleParams {
    DEFINE_PARAMETERS(
        (ParamFloat<px4::params::MC_ROLL_P>) _param_mc_roll_p
    )

    void Run() {
        // 每次循环都会读取最新值
        float roll_p = _param_mc_roll_p.get();  // ← 自动获取最新值
        // ...
    }
};
```

这类参数修改后**立即生效**，不需要重启。

#### 类型2: 启动时生效的参数（reboot_required: true）
```yaml
# src/modules/ekf2/params_multi.yaml
EKF2_MULTI_IMU:
  description:
    short: Multi-EKF IMUs
  type: int32
  default: 0
  reboot_required: true  # ← 标记需要重启
  min: 0
  max: 4
```

**为什么需要重启**：
```cpp
// src/modules/ekf2/EKF2.cpp:2788-2793
int EKF2::task_spawn(int argc, char *argv[])
{
    int32_t sens_imu_mode = 1;
    param_get(param_find("SENS_IMU_MODE"), &sens_imu_mode);
    // ↑ 只在task_spawn时读取一次！

    if (sens_imu_mode == 0) {
        multi_mode = true;
        // 创建多个EKF2实例
    } else {
        // 创建单个EKF2实例
    }
    // task_spawn之后，EKF2已经创建，无法动态改变实例数量
}
```

**需要重启的参数示例**：
- `SENS_IMU_MODE` - 影响传感器模块启动
- `EKF2_MULTI_IMU` - 影响EKF2实例数量
- `SYS_AUTOSTART` - 影响机架配置
- 传感器校准参数 - 影响驱动初始化
- 串口配置参数 - 影响设备驱动

### 9.2 参数修改后的存储时机

**时机1: 立即保存（autosave启用）**
```
用户修改参数
  ↓
param_set() 被调用
  ↓
params_unsaved.set(param)  # 标记未保存
  ↓
ParamAutosave检测到unsaved参数
  ↓
延迟2秒
  ↓
param_save_default()  # 自动保存到SD卡
```

**时机2: 手动保存**
```bash
nsh> param set SENS_IMU_MODE 0
# 参数在内存中立即生效，但未持久化
nsh> param save
# 现在持久化到SD卡
```

**时机3: 关机保存（如果autosave禁用）**
```cpp
// src/lib/parameters/parameters.cpp
// 系统关机时自动保存（如果有未保存的参数）
```

## 11. 参数修改的四种方法对比

### 11.1 方法对比表

| 方法 | 修改位置 | 生效时机 | 持久性 | 优先级 | 适用场景 |
|------|---------|---------|--------|--------|---------|
| **修改rc.board_defaults** | `boards/*/init/rc.board_defaults` | 重新编译固件 | 永久（固件中） | 低（可被用户覆盖） | 板级默认配置 |
| **修改/fs/microsd/etc/extras.txt** | SD卡 | 每次启动 | 永久（SD卡） | 高（每次启动执行） | 用户自定义启动配置 |

| **QGC参数页** | 内存→SD卡 | 立即（部分需重启） | 永久（SD卡） | 最高（用户配置） | 图形化配置 |

**优点**：
- 适合设置板级特定的默认值
- 所有该型号飞控统一配置
- 不会被参数重置清除

**缺点**：
- 需要重新编译固件
- 需要刷写固件
- 不能动态修改

**适用场景**：
- 开发新飞控板
- 为客户定制固件
- 批量生产配置

**缺点**：

- 可能被用户误删

**适用场景**：

## 13. 参数优先级详解

### 13.1 参数值的覆盖顺序

```
┌─────────────────────────────────────────────────────────────────┐
│  启动时参数值的确定过程                                         │
└─────────────────────────────────────────────────────────────────┘

步骤1: 固件默认值 (firmware_defaults)
  SENS_IMU_MODE = 1  # 来自 PARAM_DEFINE_INT32(SENS_IMU_MODE, 1)

步骤2: 导入用户参数 (param import /fs/microsd/params)
  如果 /fs/microsd/params 中有 SENS_IMU_MODE:
    user_config.set(SENS_IMU_MODE, 0)  # 覆盖为0
  否则:
    保持 firmware_defaults 的值 (1)

步骤3: 执行 rc.board_defaults (param set-default)
  param set-default SENS_IMU_MODE 1
    ↓
  检查: user_config中是否已有SENS_IMU_MODE？
    ├─ 是 (用户已修改) → 不覆盖，保持用户值 (0)
    └─ 否 (用户未修改) → runtime_defaults.set(SENS_IMU_MODE, 1)

步骤4: 执行 /fs/microsd/etc/extras.txt (param set)
  param set SENS_IMU_MODE 0
    ↓
  强制覆盖: user_config.set(SENS_IMU_MODE, 0)  # 无论之前是什么

最终结果: SENS_IMU_MODE = 0 (extras.txt的值)
```

### 13.2 param set vs param set-default

| 命令 | 作用层 | 覆盖行为 | 使用场景 |
|------|--------|---------|---------|
| **param set** | user_config | **强制覆盖** | 用户配置、运行时修改 |
| **param set-default** | runtime_defaults | **仅当用户未修改时** | 启动脚本、默认值 |

**示例**：
```bash
# 场景1: 用户未修改过参数
param set-default SENS_IMU_MODE 0  # 生效，设为0
param get SENS_IMU_MODE  # 输出: 0

# 场景2: 用户已修改过参数
param set SENS_IMU_MODE 1  # 用户修改
param save  # 保存到SD卡
# ... 重启 ...
param set-default SENS_IMU_MODE 0  # 不生效！保持用户值1
param get SENS_IMU_MODE  # 输出: 1 (用户值)

# 如果要强制修改
param set SENS_IMU_MODE 0  # 强制覆盖
```

### 14.2 存储位置判断逻辑

**文件**: `src/lib/parameters/parameters.cpp`

**第729-744行**: 存储后端选择
```cpp
int param_set_default_file(const char *filename)
{
	#ifdef FLASH_BASED_PARAMS
		// Flash模式：忽略filename参数，总是使用Flash
		(void)filename;
		return 0;
	#else
		// SD卡模式：使用传入的filename
		if (param_default_file != nullptr) {
			free(param_default_file);
		}

		if (filename) {
			param_default_file = strdup(filename);  // ← 设置文件路径
		}

		return 0;
	#endif
}
```

**第807-843行**: 保存逻辑
```cpp
int param_save_default(bool blocking)
{
	const char *filename = param_get_default_file();

	if (filename) {
		// ========== SD卡/文件系统存储 ==========
		int fd = ::open(filename, O_WRONLY | O_CREAT | O_TRUNC, ...);
		param_export_internal(fd, nullptr);  // 写入BSON
		::close(fd);

	} else {
		// ========== Flash存储 ==========
		flash_param_save(nullptr);  // 写入MCU Flash
	}
}
```

### 14.3 何时使用Flash存储？

**自动决定**（编译时）：
- 如果定义了 `FLASH_BASED_PARAMS`  → Flash存储
- 如果未定义 → SD卡存储（需要SD卡支持）

**Flash存储的飞控示例**：
- Omnibus F4
- Matek F405
- Holybro Kakute H7 Mini（部分型号）

**原因**：
- 体积小，无SD卡槽
- 降低成本
- 减少故障点（SD卡可能松动）

## 15. 参数文件的详细结构

### 15.1 BSON格式说明

**文件**: `src/lib/tinybson/tinybson.h`

BSON（Binary JSON）是一种二进制编码格式，用于紧凑存储参数。

**结构**：
```
[Header]
  ├─ Magic Number: 0x67736f62 ("bson" in little-endian)
  ├─ Document Size: 4 bytes

[Parameters]
  ├─ Parameter 1:
  │   ├─ Type: 0x10 (int32) 或 0x01 (float)
  │   ├─ Name: "SENS_IMU_MODE\0"
  │   └─ Value: 4 bytes (int32) 或 8 bytes (float)
  ├─ Parameter 2:
  │   └─ ...

[Footer]
  └─ Null terminator: 0x00
```

**导出为可读格式**：
```bash
# 方法1: 使用bsondump
nsh> bsondump /fs/microsd/params

# 方法2: 使用param export
nsh> param export /fs/microsd/params_readable.txt
```

### 15.2 params文件的完整示例

**导出的文本格式**（params_readable.txt）：
```
# PX4 Parameter Export
# Version: 1
# Timestamp: 2025-10-29 12:34:56

BAT1_A_PER_V 40.000000
BAT1_N_CELLS 4
BAT1_V_CHARGED 4.200000
BAT1_V_DIV 21.200000
BAT1_V_EMPTY 3.200000
SENS_IMU_MODE 0
EKF2_MULTI_IMU 2
EKF2_MULTI_MAG 1
SYS_AUTOSTART 4001
...
```

## 18. 常见问题解答

### 18.1 Q: 修改rc.board_defaults需要重新编译吗？

**A: 是的**

rc.board_defaults被编译进固件的ROMFS，修改后需要：
```bash
make micoair_h743_default  # 重新编译
make micoair_h743_default upload  # 上传固件
```

### 18.2 Q: QGC修改参数后立即生效还是重启后生效？

**A: 分两种情况**

**立即生效的参数**（reboot_required: false）：
- 控制参数（MC_ROLL_P, MC_PITCH_P 等）
- 滤波器参数
- 大部分运行时参数

**重启后生效的参数**（reboot_required: true）：
- `SENS_IMU_MODE` - 影响启动流程
- `EKF2_MULTI_IMU` - 影响EKF2实例数量
- `SYS_AUTOSTART` - 机架类型
- 传感器校准参数

**如何判断**：
```bash
# 查看参数定义
# src/modules/ekf2/params_multi.yaml
EKF2_MULTI_IMU:
  reboot_required: true  # ← 这里！
```

### 18.3 Q: QGC修改参数后存到哪里？

**A: 自动存到SD卡的 `/fs/microsd/params` 文件**

**源码证据**：
1. QGC发送PARAM_SET → mavlink_parameters.cpp处理
2. param_set() 更新内存
3. ParamAutosave检测到未保存参数
4. 2秒后自动调用 param_save_default()
5. 写入到 param_get_default_file() 返回的路径
6. 对于MicoAir H743，就是 `/fs/microsd/params`

### 18.4 Q: 直接修改SD卡params文件可行吗？

**A: 理论可行，但不推荐**

**问题**：
- params是BSON二进制格式，不能用文本编辑器
- 手动修改容易损坏文件结构
- CRC校验可能失败

**推荐方法**：
1. 使用 `param export` 导出为文本
2. 修改文本文件
3. 使用 `param import` 重新导入
4. 使用 `param save` 保存

**或者**：
- 使用 `/fs/microsd/etc/extras.txt` （文本格式）

### 18.5 Q: 为什么有时候参数修改后不生效？

**可能原因**：

**原因1: 使用了param set-default但用户已修改过**
```bash
# rc.board_defaults中
param set-default SENS_IMU_MODE 0  # 不生效！

# 解决: 用户参数优先级更高
param set SENS_IMU_MODE 0  # 强制修改
```

**原因2: 参数需要重启**
```bash
param set EKF2_MULTI_IMU 2  # 修改了
# 但不会立即创建新EKF2实例，需要重启
reboot  # 重启后生效
```

**原因3: 参数保存失败**
```bash
nsh> param set SENS_IMU_MODE 0
nsh> # 忘记 param save！
nsh> reboot
# 重启后恢复旧值
```

**原因4: SD卡故障**
```bash
# 检查SD卡状态
nsh> df
Filesystem      Size  Used  Avail  Use%  Mounted on
/dev/mmcsd0    32GB  2GB   30GB   6%    /fs/microsd

# 检查参数文件
nsh> ls -l /fs/microsd/params
-rw-r--r-- 1 root root 4096 Oct 29 12:34 params

# 测试写入
nsh> param save
# 如果失败，可能SD卡有问题
```

## 20. 总结

### 20.1 核心结论

1. **rc.board_defaults被硬编码到固件**
   - 编译时打包进ROMFS
   - 运行时从 `/etc/init.d/rc.board_defaults` 读取
   - 修改需要重新编译固件

2. **SD卡参数文件**
   - 主文件：`/fs/microsd/params` (BSON格式)
   - 备份文件：`/fs/microsd/params_backup`
   - 用户脚本：`/fs/microsd/etc/extras.txt` (文本，推荐)

3. **QGC修改参数的流程**
   - 通过MAVLink发送PARAM_SET
   - PX4立即更新内存中的值
   - 2秒后自动保存到SD卡 (`/fs/microsd/params`)
   - 部分参数需要重启才能生效

4. **直接修改SD卡文件**
   - 推荐方法：编辑 `/fs/microsd/etc/extras.txt`
   - 不推荐直接编辑 `params` 文件（二进制格式）
   - 可以用 `param export/import` 进行文本转换

5. **参数存储位置由编译时决定**
   - 有 `FLASH_BASED_PARAMS` → MCU Flash
   - 无 `FLASH_BASED_PARAMS` → SD卡 (`CONFIG_BOARD_PARAM_FILE`)
   - MicoAir H743: SD卡存储

### 20.2 最佳实践

**开发新飞控板**：
- 在 `rc.board_defaults` 中设置板级默认值
- 使用 `param set-default` 命令

**单个飞控配置**：
- 使用 `/fs/microsd/etc/extras.txt`
- 文本格式，易于版本控制

**现场调试**：
- 使用 QGC 或 NSH 命令
- 立即生效，方便迭代

**批量部署**：
- 导出标准参数文件
- 复制 `params` 文件到所有飞控
