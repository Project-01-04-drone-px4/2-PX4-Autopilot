## 二、频率分辨率计算

### 2.1 核心公式

**✅ 您的理解完全正确！**

```
FFT 频率分辨率 (Hz) = 采样率 (Hz) / FFT 窗口大小 (样本数)

resolution_hz = sample_rate / fft_window_size
```

**反比关系**：
- 样本越多 → 分辨率越小 → **越精确** ✅
- 样本越少 → 分辨率越大 → 越粗糙

---

### 2.2 实际计算表格

假设陀螺仪采样率 = 2000 Hz（BMI088）：

| FFT 窗口 | 公式 | 分辨率 | constrain 后带宽 | 评价 |
|---------|------|--------|----------------|------|
| 128 | 2000/128 | 15.625 Hz | 15.625 Hz | 低精度，快更新 |
| **256** | **2000/256** | **7.8125 Hz** | **8 Hz** | 触及下限 |
| **512** | **2000/512** | **3.906 Hz** | **8 Hz** | ✅ **默认配置** |
| **1024** | **2000/1024** | **1.953 Hz** | **8 Hz** | 高精度，慢更新 |
| 2048 | 2000/2048 | 0.977 Hz | 8 Hz | 超高精度，很慢 |
| 4096 | 2000/4096 | 0.488 Hz | 8 Hz | 极高精度，极慢 |

假设陀螺仪采样率 = 8000 Hz（高性能 IMU）：

| FFT 窗口 | 公式 | 分辨率 | constrain 后带宽 | 评价 |
|---------|------|--------|----------------|------|

| **512** | **8000/512** | **15.625 Hz** | **15.625 Hz** | ✅ **理想** |
| **1024** | **8000/1024** | **7.8125 Hz** | **8 Hz** | 触及下限 |

### 3.2 计算时间复杂度

**FFT 计算复杂度**：`O(N × log₂N)`

| 窗口大小 N | 复杂度 | 相对时间 | 实际时间估算 |
|-----------|--------|---------|-------------|
| 256 | 256 × 8 = 2,048 | 1× | ~50 μs |
| **512** | 512 × 9 = 4,608 | **2.25×** | **~110 μs** |
| 1024 | 1024 × 10 = 10,240 | 5× | ~250 μs |
| 2048 | 2048 × 11 = 22,528 | 11× | ~550 μs |
| 4096 | 4096 × 12 = 49,152 | 24× | ~1200 μs |

**说明**：
- STM32H743 主频 480 MHz
- CMSIS-DSP 优化的 FFT（使用硬件加速）
- 实际时间取决于具体实现

### 3.4 更新延迟

**FFT 更新延迟** = 收集样本时间 + FFT 计算时间

#### 收集样本时间

```
延迟 (秒) = 窗口大小 / 采样率

例如（采样率 2000 Hz）：
  256 样本 → 256 / 2000 = 0.128 秒 = 128 ms
  512 样本 → 512 / 2000 = 0.256 秒 = 256 ms
  1024 样本 → 1024 / 2000 = 0.512 秒 = 512 ms
```

**注意**：代码使用 75% 重叠（`GyroFFT.cpp:422-424`）：

```cpp
// 3/4 overlap
const int overlap_start = _imu_gyro_fft_len / 4;
memmove(&gyro_data_buffer[axis][0], &gyro_data_buffer[axis][overlap_start],
        sizeof(q15_t) * overlap_start * 3);
buffer_index = overlap_start * 3;
```

**实际更新间隔**（75% 重叠）：

```
更新间隔 = 窗口大小 × 0.25 / 采样率

例如（采样率 2000 Hz）：
  512 样本 → 512 × 0.25 / 2000 = 64 ms

即每 64 ms 更新一次 FFT 结果
```

## 四、分辨率与精度的关系

### 4.1 频率检测精度

**FFT 频率量化**：

```
假设真实振动频率 = 83.5 Hz
FFT 分辨率 = 8 Hz

FFT 频率bins（频点）：
  ..., 72 Hz, 80 Hz, 88 Hz, 96 Hz, ...
                ↑
           最接近 83.5 Hz

FFT 检测结果：80 Hz
实际误差：|83.5 - 80| = 3.5 Hz
最大误差：±分辨率/2 = ±4 Hz
```

**不同分辨率的检测精度**：

| 窗口大小 | 分辨率 | 频点间隔 | 最大误差 | 示例检测 |
|---------|--------|---------|---------|----------|
| 256 | 7.81 Hz | 7.81 Hz | ±3.9 Hz | 真实 83.5 → 检测 78.1 或 85.9 |
| **512** | **3.91 Hz** | **3.91 Hz** | **±1.95 Hz** | **真实 83.5 → 检测 82.0 或 85.9** |
| 1024 | 1.95 Hz | 1.95 Hz | ±0.98 Hz | 真实 83.5 → 检测 82.0 或 84.0 |
| 2048 | 0.98 Hz | 0.98 Hz | ±0.49 Hz | 真实 83.5 → 检测 83.0 或 84.0 |

---

### 4.2 可视化说明

#### 窗口 256（分辨率 7.81 Hz）

```
频谱bins：
  │       │       │       │       │       │
  64      72      80      88      96     104  Hz

真实振动 = 83.5 Hz
  → 落在 [80, 88] 之间
  → 量化到最近的 80 或 88
  → 误差 ±3.5 Hz
```

#### 窗口 1024（分辨率 1.95 Hz）

```
频谱bins（更密集）：
  │ │ │ │ │ │ │ │ │ │ │ │
  78 80 82 84 86 88 90 92 94  Hz

真实振动 = 83.5 Hz
  → 落在 [82, 84] 之间
  → 量化到 82 或 84
  → 误差 ±0.5 Hz  ← 更精确！
```

|------|--------|---------|-----|----------|

#### 5.2.3 IMU_GYRO_FFT_MIN/MAX（频率范围）

```c
// parameters.c:52, 63
PARAM_DEFINE_FLOAT(IMU_GYRO_FFT_MIN, 30.f);
PARAM_DEFINE_FLOAT(IMU_GYRO_FFT_MAX, 150.f);
```

**作用**：限制 FFT 分析的频率范围。

**原因**：
- 低频（< 30 Hz）：通常是飞行动作，不是振动
- 高频（> 150 Hz）：可能是传感器噪声，不是结构振动

**示例**：

```
采样率 = 2000 Hz
FFT 窗口 = 512
奈奎斯特频率 = 1000 Hz

理论 FFT 范围：0 - 1000 Hz
实际分析范围：30 - 150 Hz  ← 参数限制

bins：
  0, 3.9, 7.8, ..., 27.3, [31.2, 35.1, ..., 148.4], 152.3, ..., 1000
                           └──────实际使用──────┘
```

---

#### 5.2.4 IMU_GYRO_FFT_SNR（信噪比阈值）

```c
// parameters.c:85
PARAM_DEFINE_FLOAT(IMU_GYRO_FFT_SNR, 10.f);
```

**作用**：峰值必须比噪声强 N dB 才被认为是有效振动。

**计算**：

```
SNR (dB) = 10 × log₁₀(峰值功率 / 噪声功率)

SNR = 10 dB：
  峰值功率 = 10 × 噪声功率
```

**阈值选择**：

| SNR 阈值 | 灵敏度 | 误检率 | 适用 |
|---------|--------|--------|------|
| 5 dB | 高（易检测） | 高（噪声可能误检） | 低振动环境 |
| **10 dB** | **中等** | **中等** | **推荐默认** |
| 20 dB | 低（难检测） | 低（只检测强振动） | 高噪声环境 |

## 八、配置调优指南

### 8.1 如何选择窗口大小？

#### 步骤 1：确定采样率

```bash
# 查看实际采样率
listener sensor_gyro_fifo

# 或查看 IMU 状态
listener vehicle_imu_status

# BMI088: 2000 Hz
# BMI270: 1600 Hz (或修改后的 3200 Hz)
```

---

#### 步骤 2：计算分辨率需求

**根据振动特性**：

| 振动类型 | 频率范围 | 变化速度 | 需要分辨率 | 推荐窗口 |
|---------|---------|---------|-----------|----------|
| 电机基频 | 30-100 Hz | 慢（秒级） | 2-5 Hz | 512-1024 |
| 电机谐波 | 100-300 Hz | 慢 | 5-10 Hz | 256-512 |
| 机架共振 | 50-150 Hz | 很慢 | 1-2 Hz | 1024+ |
| 快速变化 | 任意 | 快（毫秒级） | 10+ Hz | 256 |

---

#### 步骤 3：验证带宽

```
分辨率 = 采样率 / 窗口大小
陷波带宽 = constrain(分辨率, 8, 30)

目标：让分辨率落在 8-30 Hz 范围内
```

**反推窗口大小**：

```
采样率 = 2000 Hz
期望带宽范围：8-30 Hz

窗口大小范围：
  最小窗口 = 2000 / 30 = 66.7 → 使用 128 或 256
  最大窗口 = 2000 / 8 = 250 → 使用 256

优化窗口 = 2000 / 15 (期望带宽) = 133 → 使用 128 或 256

实际上，窗口 > 250 时，带宽会被限制到 8 Hz（下限保护）
```

---

### 8.2 性能调优

#### 场景 1：CPU 负载过高

**现象**：
- `gyro_fft status` 显示 FFT 时间过长（> 200 μs）
- 系统 CPU 占用高

**解决**：

```bash
# 减小窗口大小
param set IMU_GYRO_FFT_LEN 256

# 或禁用 FFT，使用 ESC RPM 代替
param set IMU_GYRO_FFT_EN 0
param set IMU_GYRO_DNF_EN 1  # 切换到 ESC RPM
```

---

#### 场景 2：检测不到振动

**现象**：
- `listener sensor_gyro_fft` 显示 peak_frequencies 全是 0
- 已知存在振动

**可能原因和解决**：

1. **SNR 阈值太高**

```bash
# 降低阈值
param set IMU_GYRO_FFT_SNR 5
```

2. **频率范围不对**

```bash
# 扩大频率范围
param set IMU_GYRO_FFT_MIN 10
param set IMU_GYRO_FFT_MAX 300
```

3. **分辨率太低**

```bash
# 增大窗口
param set IMU_GYRO_FFT_LEN 1024
```

---

#### 场景 3：陷波效果不好

**现象**：
- FFT 检测到峰值，但振动仍存在

**可能原因和解决**：

1. **分辨率太粗糙**

```bash
# 增大窗口提高精度
param set IMU_GYRO_FFT_LEN 1024
```

2. **更新太慢**

```bash
# 减小窗口加快响应
param set IMU_GYRO_FFT_LEN 256
```

3. **带宽不够**

带宽是自动计算的，无法直接调整。如果觉得不够，考虑：
- 调整窗口大小改变分辨率
- 或使用静态陷波滤波器（更宽带宽）

## 九、窗口大小对系统的综合影响

### 9.1 数据流时间线

以 512 窗口为例（采样率 2000 Hz）：

```
时间轴（毫秒）：
0    32   64   96   128  160  192  224  256
│────│────│────│────│────│────│────│────│
     ↓    ↓    ↓    ↓    ↓    ↓    ↓    ↓
    收集 收集 FFT  收集 FFT  收集 FFT  收集
    128  128  计算 128  计算 128  计算 128
    样本 样本     样本     样本     样本

说明：
- 前 256 ms：收集 512 个样本
- 之后每 64 ms：新增 128 样本（25%），做一次 FFT
- 75% 重叠：保证连续性
```

---

### 9.2 实时性分析

| 窗口大小 | 首次 FFT 延迟 | 后续更新间隔 | 频率变化响应 | 适合动态场景？ |
|---------|--------------|-------------|-------------|---------------|
| 256 | 128 ms | 32 ms | 快 | ✅ 是 |
| **512** | **256 ms** | **64 ms** | **适中** | ✅ **推荐** |
| 1024 | 512 ms | 128 ms | 慢 | ⚠️ 较慢 |
| 2048 | 1024 ms | 256 ms | 很慢 | ❌ 不适合 |

---

### 9.3 内存和 CPU 对比

**以 STM32H743 为例**（480 MHz, 1 MB RAM）：

| 窗口 | RAM | RAM% | FFT 时间 | CPU% (800Hz 更新) | 实时性 |
|------|-----|------|---------|------------------|--------|
| 256 | 3.5 KB | 0.34% | ~50 μs | 0.4% | 优秀 |
| **512** | **7 KB** | **0.68%** | **~110 μs** | **0.9%** | **良好** |
| 1024 | 14 KB | 1.37% | ~250 μs | 2.0% | 可接受 |
| 4096 | 56 KB | 5.47% | ~1200 μs | 9.6% | 较差 |

**说明**：
- CPU% = (FFT 时间 × 更新频率) / 1秒
- 512 窗口：每 64ms 更新 → 15.6 Hz → 110μs × 15.6 ≈ 0.17%
- 实际会更高（包括数据处理、峰值检测等）

## 十一、常见问题

### Q1: 为什么默认是 512 而不是 256 或 1024？

**A**: 512 是经验平衡值：

```
512 样本的优势：
  ✓ 分辨率适中（~4 Hz）
  ✓ 更新适中（~64 ms）
  ✓ CPU 负载合理
  ✓ 内存占用小
  ✓ 适合大多数飞行器

256: 太粗糙，难以精确定位
1024: 太慢，动态响应差
```

---

### Q2: 可以用 4096 吗？

**A**: 理论支持，但**不推荐**：

```c
// GyroFFT.cpp - 代码中注释掉了
// case 4096:
//     buffers_allocated = AllocateBuffers<4096>();
//     break;
```

**原因**：
- 内存占用：56 KB（较大）
- FFT 时间：~1.2 ms（很长）
- 更新间隔：512 ms（太慢）
- 首次延迟：2 秒（过慢）

**适用场景**：仅用于地面分析，不适合实时飞行。

---

### Q3: 如何知道我的板子支持哪些窗口大小？

**A**: 代码中硬编码支持 256, 512, 1024：

```bash
# 尝试设置
param set IMU_GYRO_FFT_LEN 1024

# 重启后检查
param show IMU_GYRO_FFT_LEN

# 如果不支持，会自动回退到 256 并显示错误
```

---

### Q4: 窗口大小可以动态改变吗？

**A**: ❌ 不可以

```c
// parameters.c:73
* @reboot_required true
```

**原因**：
- 需要重新分配内存缓冲区
- 需要重新初始化 FFT 库
- 改变后必须重启生效

---

### Q5: 高采样率 IMU（如 8000 Hz）怎么配置？

**A**: 可以用更大的窗口：

```
采样率 = 8000 Hz

窗口 512:
  分辨率 = 8000 / 512 = 15.6 Hz
  带宽 = 15.6 Hz  ✓ 理想

窗口 1024:
  分辨率 = 8000 / 1024 = 7.8 Hz
  带宽 = 8 Hz (限制)  ✓ 可用

窗口 2048:
  分辨率 = 8000 / 2048 = 3.9 Hz
  带宽 = 8 Hz (限制)  ✓ 高精度
```

## 十二、总结

### ✅ 回答您的问题

1. **FFT 样本数由参数决定吗？**
   - ✅ **是的** - `IMU_GYRO_FFT_LEN` 参数

2. **还是硬编码？**
   - ❌ 不是硬编码
   - 用户可通过参数调整

3. **样本越大，分辨率越小是吧？**
   - ✅ **完全正确！**
   - 分辨率 = 采样率 / 窗口大小
   - 反比关系

4. **是不是更精确，但计算时间增加？**
   - ✅ **正确！**
   - 精度提高（分辨率小）
   - FFT 时间增加（O(N log N)）

5. **当前默认样本数？**
   - **512 样本**

---

### 核心公式

```
分辨率 = 采样率 / FFT 窗口大小

示例（采样率 2000 Hz）：
  窗口 256  → 分辨率 7.81 Hz
  窗口 512  → 分辨率 3.91 Hz  ← 默认
  窗口 1024 → 分辨率 1.95 Hz
```
